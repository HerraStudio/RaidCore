# raid

对局配置、进入、撤离、死亡、结算、计时与撤离特效。

默认撤离烟雾使用 Photon 的 `VANILLA` 合成模式，对当前场景深度执行遮挡；不继承全局 `LATE`，避免关闭光影时穿透在半透明阶段绘制的不透明地图模型。[烟雾修复与原生验证](../docs/EVACUATION_SMOKE.md)。

Raid 对局默认30分钟（1800秒、36000个服务端 tick），同局所有玩家共用一个ID和时钟。`/raid join` 加入等待，管理员 `/raid start` 统一开局并传送出生点；`/raid start <玩家选择器>` 可批量登记并开局。默认至少2人，须配置2个不同出生点；管理员 `/raid minplayers 1` 可单人调试。等待不消耗时间，小地图在开局后沿用金色 `m:ss` 数字与脉冲效果，最后60秒转红。撤离点自身的停留倒计时独立显示。

时间由服务端推进；归零后结算为“行动超时”并自动返回大厅，沿用现有结算与携带物品规则。撤离、死亡、终止、断线后清除地图计时；大厅和普通世界不自动启动。服务端暂停或更新延迟时，客户端只预测最多5个 tick，不会自行判定超时。

一人撤离、死亡或退出后，其余成员继续本局；结束成员在整局结束前不能重新加入，即使已经确认结算。全员结束并且在线成员已返回后清理共享对局状态；离线成员的结果与待返回大厅标记继续保存。`/raid leave` 离开等待或中断参与；管理员 `/raid stop` 停止整局，`/raid status` 显示ID、阶段、维度与成员。

1.1.0 完成共享生命周期和状态清理，下一局的容器/保险箱/地图恢复及带出物品提交仍属于Core Loop M2/M3。具体实现与双客户端检查见 `../docs/CORE_LOOP_M1.md`。

管理员 `/raid duration` 查看默认时长，`/raid duration <分钟>` 设置1–1440分钟。配置随世界数据保存，只影响下一次入场；正在进行的对局保留入场时的时长。旧配置和旧对局记录缺少时长字段时回退到30分钟。

`/map timer <时长>` 与 `/map timer reset` 保留手动计时，客户端的 `general.match_timer_seconds` 仅用于手动默认时长。Raid 对局使用服务端配置；外部 `TacticalMapApi.registerTimerProvider` 仍保持最高优先级。

源码位于 `src/main/java`，资源位于 `src/main/resources`，对应单元测试位于 `src/test/java`（按需添加）。

由根目录 Gradle 的 main/test 源集统一编译并打入 RaidCore 的单个 JAR；Java 包名与资源命名空间保持兼容。
启动入口及模组描述文件由项目根目录 `src/main` 统一管理。模块说明见 `../docs/MODULES.md`。
